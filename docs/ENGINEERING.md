# 工程规范

本规范与根目录 [AGENTS.md](../AGENTS.md) 一起约束后续开发。现有代码不全部符合目标规范，存量整改在 [ENG-001/002](BACKLOG.md) 跟踪。

## 代码与模块

- 使用 nullable、隐式 using、四空格缩进和文件范围命名空间。公共类型/成员使用 PascalCase，局部变量/参数使用 camelCase，接口使用 `I` 前缀。
- 每个 class 必须有简明准确的中文职责注释；核心实现解释业务约束、状态一致性、幂等性和兼容性。公开 record/interface 同样建议说明语义；生成文件通过生成源或工具维护。
- 一个方法表达一个业务步骤；同一行不堆放多个公开成员或复杂分支。命名优先描述业务，不用 `Manager`/`Helper` 隐藏无关职责。
- 纯规则接收显式输入并返回结果；时间、随机、IO 由运行层注入或传入。异步 IO 全程 await，不使用 `.Result`/`.Wait()` 阻塞请求，也不通过 `Task.Run` 脱离 Grain 调度修改状态。
- 新抽象需说明变化点、调用者和测试方式；优先复用内置 DI/Options/日志等设施。模式选型见 [架构](ARCHITECTURE.md)，不强制每层都建立 Repository、Service 和工厂。
- `GameServer.Abstractions` 只允许依赖 Contracts；独立玩法模块只引用 Abstractions/Contracts，不得反向依赖 Gateway、Grains 或 Infrastructure。模块接入规则见[模块开发指南](guides/modules.md)。

## 一致性与兼容性

每个写操作在实现前说明权威状态、前置条件、操作号范围、命令指纹、提交点、重复结果和结果未知时的恢复行为。外部投影明确延迟、幂等键、重建与对账方式。

网络消息编号、MessagePack Key、Orleans 字段 ID/类型标识、EF schema 和内容版本分别演进。不得重用已发布编号；不能在格式整理中重排依赖自动生成 ID 的持久化字段。由自动编号转为显式编号前，先取得原生成映射并增加旧数据读取测试。

首个客户端正式发布前，实时协议只维护当前结构，可以直接调整消息和字段，不为未使用的报文保留版本分支。客户端发布后再冻结对外契约；届时公共结构破坏性变更必须使用新版本并提供迁移说明，兼容验证至少包含旧客户端报文。持久化状态和已导入内容不受这项简化影响，仍需提供旧数据缺省语义，并验证旧状态重激活和新旧内容共存。

数据库迁移需说明数据保留、执行方、前后版本兼容和失败恢复。多节点自动迁移及滚动升级能力必须实测，不能由单节点启动成功推断。不可逆数据变更采用备份/恢复或前向修复计划，不声称所有迁移都支持向下回滚。

## 验证分层

| 层级 | 验证内容 | 运行方式 |
| --- | --- | --- |
| 领域 | 边界数值、状态迁移、确定性规则 | `dotnet test OrleansGameService.slnx` |
| 契约 | MessagePack 序列化往返、消息分发、错误语义 | 同上，客户端发布后增加固定报文兼容用例 |
| Grain | 重放、并发请求、重激活、提交前后失败 | 真实 Orleans 测试集群与故障注入 |
| 持久化/端到端 | 真实 PostgreSQL、Redis、HTTP/WebSocket 与重启 | `pwsh -File scripts/Test-Integration.ps1` |
| 分布式/容量 | 多节点、热点、慢连接、长时间运行、备份恢复 | 后续提供脚本与报告，目前未完成 |

测试验证外部行为和不变量，不逐行复刻实现。修改游戏校验、序列化或幂等性必须补针对性测试；纯文档或格式改动不添加无意义业务测试。普通测试中的集成跳过不视为端到端通过。

现有 CI 已配置构建、EF 模型变更检查、普通测试和 Compose 验证。本轮添加的编辑器规则与 PR 模板只提供协作基线；SDK 固定、自动格式/依赖门禁及安全扫描属于后续任务。

## 文档与完成定义

功能完成必须同时满足：

1. 行为和错误路径符合验收条件，相关测试通过；未运行的验证明确标记。
2. 模块职责清晰、class 中文注释齐全，无新增不合理跨项目依赖。
3. 持久化、协议、配置和内容变更附兼容说明；复杂决策附 ADR。
4. 对应专题文档包含用法、请求/响应或内容样例、错误/重试、限制和代码入口。
5. 开发路线与待办状态同步；无密钥及生成产物进入提交。

ADR 使用“背景、决策、替代方案、代价、验证、状态”结构。设计提案不等于已落地架构；被替代的决策保留历史。

## 运维与发行

采用版本化发行说明，分别列出公共协议、持久化、内容包及环境变量变化。正式发布前确定许可证、支持版本、升级和恢复路径；NuGet 发布和仓库公开是独立的发行步骤。

生产部署从环境注入密钥和连接字符串；配置必须在启动时验证。存活探针反映进程存活，就绪探针反映是否可接收业务；实际依赖检查需要注册实现，只有健康路由不足以证明数据库可用。[ASP.NET Core 官方健康检查说明](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/health-checks?view=aspnetcore-10.0)

日志记录命令、操作、会话和内容版本关联；不要把角色 ID 等高基数字段直接作为指标标签。资产操作提供审计、故障恢复与对账入口；备份只有通过恢复演练才算完成验证。
