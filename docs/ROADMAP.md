# MMORPG 框架开发路线

规划基线：2026-09-07。阶段编号用于开发排序，不代表已发布版本，也不承诺日历工期。近期范围见 [BACKLOG](BACKLOG.md)。

## 目标与默认假设

提供服务器权威、可组合、可测试、可运维的 MMORPG 框架，并交付一个能够验证完整流程的示例游戏。首条验证路径沿用当前二维坐标、区域实例和 RPG 战斗规则；特定题材、职业、数值与地图属于示例内容。

框架分为通用核心、可选玩法模块、基础设施适配器和示例游戏。先验证模块职责，再提取独立包；早期维持现有解决方案，避免一次性重写。高频空间模拟不预设为每个实体一个 Grain，应依据区域热点和调用开销测量选择粒度。

首个稳定版本不以无缝世界、跨洲实时战斗、自研物理引擎、任意脚本热执行或商业运营后台全家桶为验收目标。目标在线人数、同屏规模和延迟预算需结合游戏节奏与部署硬件确定，不把 Orleans 的扩展能力等同于已验证的游戏容量。

## 当前能力盘点

“已有基础”表示存在实现及部分测试，不代表功能完整或生产可用。

| 能力 | 当前状态与证据 | 主要缺口 |
| --- | --- | --- |
| 账号、鉴权、角色 | `Program.cs`、`AccountGrain`；Identity/JWT、角色归属校验 | 会话替换、注销/封禁生效、账号风控与管理审计 |
| 区域与移动 | `CharacterGrain`、`ZoneGrain`；入区、容量、切区恢复及服务器时间预算 | 地图约束、离线成员清理、分线 |
| 实时通信 | `WebSocketGameEndpoint`；单一 MessagePack 协议、分片接收、64 KiB 上限 | 多人推送、AOI、序列与补同步、连接级限流和背压 |
| 战斗与内容 | 属性、技能、资源、装备、Buff、NPC、击杀任务、掉落 | 怪物主动 AI、完整成长、物品实例、技能目标扩展 |
| 模块扩展 | 显式编译期模块、依赖校验、字符串效果类型、类型化内容节、示例吸血模块 | 自定义命令/Grain 状态、独立发行包和第二个完整宿主 |

| 内容版本 | JSON 校验、导入存库、区域固定版本、启动加载历史版本 | 在线多节点同步、并发发布、回滚与加载失败诊断 |
| 工程与运维 | CI、Compose、迁移检查、真实 Grain 故障注入测试 | 实际依赖就绪检查、指标导出与业务告警、容量与备份恢复报告 |

## 阶段与验收

### M0：正确性与工程基线（下一阶段）

- 补齐服务器时间与移动预算、有限坐标校验、NPC 任务归属/距离约束，以及随机掉落不可由客户端操作号操纵的设计。
- 补齐新增/修改 class 的中文职责注释，按领域职责整理高密度代码；将宿主装配、协议处理与规则实现保持清晰。
- 建立协议发布基线与状态兼容审查、SDK 与依赖管理方案、架构依赖检查，完善配置启动校验、就绪检查及业务指标。
- 交付现行 HTTP/WebSocket 协议、错误码和重试文档。

验收：快速发送多个合法小步不能突破服务器速度预算；重试与重激活不多移动、不重复结算；交互不能绕过权威约束；当前协议序列化往返和恢复测试继续通过；Compose 主流程通过；依赖异常能被就绪检查及日志定位。

### M1：多人在线闭环（依赖 M0）

- 会话注册、单角色会话策略、会话代次、心跳、到期与断线清理。
- 有界发送队列、慢客户端处理、连接内串行发送、按账号/会话限制命令速率。
- 区域广播、AOI（按兴趣范围筛选可见实体）、实体进入/离开/变化通知。
- 快照序列、增量、断线重连、丢失增量后的全量恢复。
- 最小可运行客户端或机器人示例，用于协议接入和多玩家验收。

验收：两个客户端可互相观察移动/战斗与离区；重连后状态收敛；旧连接在会话被替换后无法继续变更状态；慢客户端不会拖住区域或其他连接；区域重启、网关断开后可清理订阅和成员。交付客户端接入与会话状态图。

### M2：可扩展 RPG 玩法（依赖 M1）

- 怪物状态机：巡逻、警戒、追击、攻击、脱战、死亡、重生；寻路作为可替换适配器。
- 经验、等级、死亡复活、技能学习/升级、Buff 叠加与周期效果、治疗和目标规则。
- 物品模板与实例分离、唯一装备、绑定、耐久、货币、消耗品、背包/仓库转移。
- 任务前置、多目标、任务链、重复任务与重置时区；掉落归属、组队奖励规则。
- 通过真实第二种规则实现验证策略接口；补充模块依赖、启动校验和示例内容包。

验收：新增职业、物品、任务等配置内容无需修改宿主；新增一种服务端效果通过受控注册和测试完成；经验与资产发放在故障重试下不重复；时间相关规则可通过可控时钟验证。交付玩法说明、内容规范和模块开发指南。

### M3：社交与经济模块（按需启用，依赖 M2 的资产规则）

- 队伍、好友、黑名单、频道聊天、公会权限与成员生命周期。
- 邮件及附件领取、直接交易、商城兑换；拍卖行作为后续独立子阶段。
- 副本队伍入场、实例生命周期、锁定/结算、排行榜及读模型重建。
- 跨角色资产操作采用显式持久化流程；定义预留、确认、取消、超时与人工修复状态。

验收：并发领取、重复确认、超时及任意提交点故障不导致资产复制或丢失；成员退出与权限变更即时遵守服务端规则；经济账本可对账；可禁用模块且不破坏核心启动。交付资产一致性 ADR 和故障处理手册。

### M4：分布式运行与容量（M1 后开始基础工作，完整验收覆盖选定玩法）

- 多节点内容发布、版本准备/激活、区域版本固定、回滚及发布审计。
- 先验证多 Silo；依据连接与计算负载决定是否拆分 Gateway 和 Silo 宿主。
- 分区/分线、热点区域治理、优雅下线、会话重连、积压补偿与运维诊断。
- 操作回执期限与归档、状态体积控制、存储写放大优化和备份恢复演练。
- 可复现机器人压测、持续运行测试、节点故障与依赖中断演练。

验收：在报告中固定 CPU/内存、节点数、存储、客户端分布、命令频率和测试时长，记录 CCU、同区人数、p50/p95/p99、错误率、带宽、GC、写入量、队列及状态体积；按压测前约定预算判定通过。至少覆盖双 Silo 故障恢复、热区域和慢客户端。先有测量，再声明容量。

### M5：开源发行（依赖 M0–M2、M4；M3 按发行范围选入）

- 确定许可证及第三方依赖/素材授权、贡献约定、安全报告渠道和维护范围。
- 核心包、可选模块和示例宿主形成清晰接入路径，提供版本化发行说明与升级指南。
- 建立预发布、兼容性矩阵、示例内容、基础客户端、部署手册和已知限制列表。
- 用第二个差异化小型示例验证复用：只替换内容和玩法策略，不复制核心实现。

验收：新使用者从干净环境按文档完成启动与玩法闭环；可创建独立宿主接入框架；升级测试和备份恢复演练通过；发行范围内不存在未说明的破坏性兼容变更。

## 排期与范围管理

每轮选择一个可独立验收的纵向功能，经过“约束与设计 → 实现 → 故障/兼容验证 → 文档 → 待办状态更新”。优先级为状态与资产正确性、多人闭环、扩展能力、容量、外围玩法。运维基础工作贯穿各阶段，不等到 M4 才处理。

近期任务使用 S（局部规则/文档）、M（跨层功能）、L（需先拆设计）表示相对规模；拿到实际开发吞吐后再估算工期。目标战斗节奏、客户端平台、CCU/同屏规模和许可证是后续需要项目负责人确定的产品约束，不阻塞当前 M0 工作。
