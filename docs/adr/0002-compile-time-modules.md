# ADR 0002：采用显式编译期模块与类型化内容节

- 日期：2026-09-07
- 状态：已采纳并实现首版基座

## 背景

原有 `IGameFeatureModule` 只能手工填充可变效果字典，效果由封闭枚举定位，内容校验绑定具体 JSON 目录实现。新增效果仍需修改核心契约，未使用的通用规则接口也没有形成可验证的替换接缝。

## 决策

二次开发包通过 `GameServerBuilder` 执行显式编译期注册。模块声明唯一 ID 和依赖，可注册标准 DI 依赖、字符串标识的 `IGameEffect`、一个强类型内容节及 `IGameContentValidator`。模块图按 ID 稳定拓扑排序并冻结；重复 ID、缺失依赖、环和效果冲突阻止启动。

JSON 内容的 `modules` 对象按模块 ID 隔离。内容先解析核心模型，再按注册类型绑定模块节并聚合校验，成功后生成进程内 `GameContentVersion`。旧内容没有模块节时，可选模块使用明确默认值；未知模块和缺失必需模块均拒绝加载。

现有 `EffectKind` 继续映射内置效果，新增 `TypeId` 作为优先的开放标识。实时协议、Grain Interface、序列化别名和持久化状态不变。

## 替代方案

- 程序集扫描会隐藏注册顺序并增加裁剪、诊断和部署差异，本轮不采用。
- 热加载程序集或脚本需要安全隔离、卸载、状态迁移及运维设计，不属于当前基座。
- 自由键值效果参数虽然灵活，但把类型错误推迟到运行期，因此采用模块级强类型内容。
- 为每种规则预先建立通用接口会形成浅模块；仅保留已有第二种实现和测试证明的效果接缝。

## 代价与限制

模块增删需要重新编译和重启。移除活动内容依赖的模块会使启动失败，而不是静默忽略。首版不开放自定义实时命令、模块 Grain 状态或生命周期，后续应以真实用例和兼容策略另行决策。

## 验证

测试覆盖模块拓扑、重复和缺失依赖、效果冲突、旧内容默认值、未知/必需/错误内容节、示例吸血结算、配置启动校验及现有协议和 Grain 恢复回归。真实 Compose 验证仍依赖可用 Docker 环境。
