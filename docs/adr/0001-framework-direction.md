# ADR 0001：以通用核心、可选玩法模块和示例游戏演进框架

- 日期：2026-09-07
- 状态：已采纳为后续开发方向；模块拆包尚未实施

## 背景

项目已具备 Orleans MMORPG MVP、基础 RPG 玩法和部分故障恢复能力。长期目标是服务多个游戏项目，兼顾可维护性、可扩展性与开源接入体验。当前 CharacterGrain、Contracts 与内容模型承载了较多具体玩法，直接增加系统会进一步耦合。

## 决策

以通用核心提供状态与连接机制，以可选模块承载玩法，以示例游戏验证组合使用。优先沿现有项目演进，先明确状态归属、缩小接口和建立兼容测试，再按真实复用需求提取包。

Grain 承担权威状态与业务流程，纯规则留在 Domain；外部依赖通过已有或有明确用途的接口接入。设计模式用于真实变化点与恢复需求。每个功能同时交付测试和文档，采用阶段验收推进。

## 替代方案

- 继续将全部玩法加入 CharacterGrain：短期直接，但会增加状态迁移和回归范围，不作为长期方向。
- 立即拆成大量 NuGet 包/微服务：尚未验证稳定接口，容易固化错误抽象并提高部署成本，暂不采用。
- 先建设动态插件/通用脚本平台：当前主要缺口是正确性与多人闭环，暂以编译期模块注册验证扩展需求。

## 代价与限制

早期允许过渡结构存在，需要在待办中明确技术债。Contracts 的拆分、角色玩法模块提取和 Gateway/Silo 分离均可能涉及兼容性；不得仅按目录移动完成。现有恢复保证应先保留，性能优化需记录一致性取舍。

## 验证

先完成服务器移动校验、会话和多人同步；用第二种真实效果/规则检验扩展接口，最终用第二个差异化示例检验复用。框架发行前需通过独立宿主接入、旧数据升级及恢复测试，具体阶段见 [路线](../ROADMAP.md)。
